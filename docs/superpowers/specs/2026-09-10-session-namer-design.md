# claude-session-namer — Design Spec

**Date:** 2026-09-10
**Status:** Implemented in v1.0.0 (2026-09-10). Amended after real-world testing: headless generation uses "lean" mode instead of `--bare` (see 4.5), the prompt is piped through stdin, and the default timeout is 20 s.
**Author:** Bruno Bola (with Claude Code)

## 1. Purpose

Every Claude Code session gets a readable, consistent title of the form
`<project> - <topic>` automatically, in every surface (CLI, VS Code
extension, Remote Control on claude.ai/code and the mobile app), on
every platform (Windows, macOS, Linux), for every account
(`CLAUDE_CONFIG_DIR` aware), with zero manual steps and zero
dependencies beyond Claude Code itself plus Node.js.

The user problem: with many parallel sessions, especially seen from a
phone via Remote Control, auto-generated or hostname-based titles are
unreadable. `bruno-w11-graceful-unicorn` says nothing; `arcva-2.0 -
Migração de faturas para V10` says everything.

## 2. Non-goals

- Do not re-implement Remote Control auto-connect. Claude Code already
  has `remoteControlAtStartup`. The plugin documents it and offers a
  one-command helper, nothing more.
- Do not touch the session transcript file. Titles are set only through
  the documented `hookSpecificOutput.sessionTitle` API.
- Do not rename sessions the user named explicitly (`--name`, `/rename`,
  rename from claude.ai). A user-set title always wins.
- Do not change terminal tab titles or the statusline. Other projects do
  that; this one names the session itself.
- No telemetry, no network calls other than the one title-generation
  request made through the user's own `claude` CLI.

## 3. Prior art and native capabilities (why this design)

Native facts, verified in the official docs on 2026-09-10:

- `SessionStart` command hooks can return `hookSpecificOutput.sessionTitle`
  (same effect as `/rename`). Input carries `source` (`startup`, `resume`,
  `clear`, `compact`, `fork`) and `session_title` when a title already
  exists. `sessionTitle` is ignored on `clear` and `compact`.
- `UserPromptSubmit` command hooks can also return `sessionTitle`, and
  receive `prompt`. Default timeout is 30 s. Async hooks cannot return
  `sessionTitle`.
- `prompt`-type hooks only return `ok`/`reason`; they cannot set titles.
  `SessionStart` does not support `prompt` hooks at all. Hence command
  hooks in Node.
- Exec-form hooks (`"command": "node", "args": [...]`) spawn without a
  shell: no quoting issues on Windows, no dependency on Git Bash or
  PowerShell. `${CLAUDE_PLUGIN_ROOT}` is substituted per argument.
- Plugin `userConfig` prompts the user for options at enable time and
  exports them to hook processes as `CLAUDE_PLUGIN_OPTION_<KEY>`.
- `claude -p` with `--setting-sources ""` runs a headless one-shot query
  that loads no user settings, hence no hooks or plugins, which is what
  makes calling Claude from inside a hook safe (no recursion).
  `--no-session-persistence` keeps it from writing a transcript. `--bare`
  would be faster but skips keychain reads, so it fails for OAuth logins.
- Claude Code already writes an `ai-title` after the first message, with
  lower priority than a hook/`/rename` title. Known VS Code issue: the
  sidebar may keep showing the `ai-title` until the session is reopened.
- Title precedence for Remote Control: `--name`/`--remote-control <name>`
  first, then `/rename`-equivalent titles, then history, then auto summary.

Community: `wpt888/cc-rename` (Haiku title on first prompt, 0 stars, not
Windows/VS Code tested), a blog script doing `project/branch` at
SessionStart, and several tab-title/statusline tools. Nothing does
`<project> - <topic>`, cross-platform, packaged as an installable
plugin, with VS Code mitigation. That is the gap.

## 4. Behaviour

### 4.1 Title format

```
<project><separator><topic>
```

- `project`: git repository root folder name when inside a git work tree
  (so all worktrees of a repo share the prefix), otherwise the cwd
  folder name. Configurable override per repo via `.session-namer.json`
  (`{"project": "ARCVA"}`) at the repo root.
- `separator`: default `" - "` (configurable).
- `topic`: 3 to 7 words, in the language of the prompt, sentence case,
  no trailing punctuation, no quotes, no emoji, no newlines. Max 60
  characters after sanitising. Generated by a fast model through a lean
  headless `claude -p` call (see 4.5).
- Full title capped at 80 characters; the topic is trimmed at a word
  boundary first, then the project name if still too long.

### 4.2 Lifecycle

| Moment | Hook | Action |
| :-- | :-- | :-- |
| Session starts (`startup`, `fork`) | SessionStart | If `session_title` is absent, emit `sessionTitle = <project>`. Never waits on the network. |
| Session resumes (`resume`) | SessionStart | If `session_title` is absent (old session never titled), emit `<project>`. If present, do nothing. |
| `/clear`, compaction | SessionStart | Do nothing (platform ignores `sessionTitle` here anyway). |
| First real prompt | UserPromptSubmit | If the session is still in "provisional" state (see 4.3), call the model, emit `<project> - <topic>`. |
| First turn ends | Stop | If the plugin set a full title in this session, re-emit the same title once, to outlive the VS Code `ai-title` rewrite. Then never again. |
| Any time | `/session-name [topic]` | Force a rename. With an argument uses it verbatim as topic; without, regenerates from the last user message. |

### 4.3 State: how the hook knows what to do

State is a tiny JSON file per session at
`$CLAUDE_CONFIG_DIR/session-namer/state/<session_id>.json`
(defaults to `~/.claude/session-namer/...`; honours `CLAUDE_CONFIG_DIR`
so two accounts never share state):

```json
{ "stage": "provisional" | "final" | "user", "title": "...", "ts": 1725926400 }
```

- `provisional`: plugin set `<project>` only.
- `final`: plugin set `<project> - <topic>`.
- `user`: a user-set title was observed; plugin will never touch it.

Rules:
- SessionStart with `session_title` present and not equal to what the
  plugin last wrote → mark `user`.
- UserPromptSubmit acts only when stage is `provisional` (or the file is
  missing and the session is new: no state file and SessionStart never
  ran, e.g. plugin enabled mid-session; in that case treat as
  provisional and go straight to final).
- State files older than 30 days are pruned opportunistically on
  SessionStart (max 200 deletions per run, never blocking).

### 4.4 Prompt eligibility (UserPromptSubmit)

Skip title generation, silently, when any of these hold:

- prompt trimmed length < 12 characters;
- prompt starts with `/` (slash command) or `!` (shell) or `#` (memory);
- prompt is only a file reference / paste marker (`@path`, `[Pasted text ...]`) without other words;
- prompt is one of a small list of greetings/acks (`ok`, `sim`, `yes`,
  `continue`, `continua`, `go`, `hi`, `olá`) — case-insensitive;
- `CLAUDE_SESSION_NAMER=off` or plugin option `enabled=false`;
- `SESSION_NAMER_NESTED=1` in env (belt-and-braces recursion guard, set
  by the plugin on its own child process even though `--bare` already
  skips hooks);
- the session is non-interactive (`claude -p`): detected via
  `CLAUDE_CODE_ENTRYPOINT` / absence of a TTY is not reliable from a
  hook, so the plugin instead honours option `name_headless=false`
  (default) and checks `process.env.CLAUDE_CODE_HEADLESS` if present;
  documented as best-effort. Headless runs cost one Haiku call at worst.

When skipped, the session keeps the provisional `<project>` title and
the next eligible prompt will try again (state stays `provisional`).

### 4.5 Topic generation

Command (exec form, spawned by the hook, not via shell):

```
claude -p --no-session-persistence --max-turns 1 --model <model> \
  --setting-sources "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --tools "" --disable-slash-commands --output-format json \
  --system-prompt "<fixed system prompt>" "<user prompt, truncated>"
```

This is "lean" mode: no user settings (so no hooks or plugins), no MCP,
no tools, no skills, one turn. Measured on 2026-09-10: about 4 to 5 s and
USD 0.004 per title with Haiku. `--bare` is faster but skips keychain
reads and therefore fails with "Not logged in" for OAuth logins; it is
opt-in via `SESSION_NAMER_BARE=1` for API-key users only.

- `model` default `haiku` (alias resolved by Claude Code); configurable.
- The user prompt is truncated to the first 1 500 characters plus, if
  longer, the last 300, to keep cost flat on huge pastes.
- System prompt (English, fixed, versioned in the repo): "Return ONLY a
  session title: 3 to 7 words describing the task, in the same language
  as the user's message, sentence case, no quotes, no trailing period,
  no emoji." Plus three few-shot examples (pt, en, es).
- Timeout 20 s (option `timeout_ms`, max 27 s; the platform hook timeout is 28 s). Claude Code startup on Windows alone takes 5 to 12 s under load. On timeout the child is killed
  (`SIGTERM`, then `SIGKILL` after 1 s; on Windows `taskkill /T /F`).
- Result parsing: read the `result` field from the JSON output; if the
  CLI returns non-JSON or an error, fall back to plain stdout; sanitise
  (strip quotes, newlines, emoji, control chars, leading "Title:" etc.);
  validate 2..12 words; otherwise treat as failure.
- Failure of any kind → exit 0 with no output. The session simply keeps
  `<project>`. A one-line reason is appended to the log (4.8). Never
  block the user's prompt, never print to stderr (stderr from a
  non-zero exit would surface to the user).
- Cost guard: at most one generation attempt per session per 60 s, and
  at most 3 attempts per session in total (state `attempts`).

### 4.6 VS Code mitigation

- Stop hook re-emits the final title exactly once (state `reasserted=true`).
- README documents that the VS Code sidebar may lag until reopen (known
  upstream issues #56014 / #60491) and that the CLI `/resume` list and
  claude.ai/code show the correct title immediately.

### 4.7 Remote Control helper

- `/session-name --remote` prints: the current title, whether
  `remoteControlAtStartup` is on, and the exact steps (`/rc` now, or set
  `remoteControlAtStartup: true` in user settings, or `claude
  --remote-control "<title>"` from a terminal). Prints only; never edits
  settings.
- Because `--remote-control <name>` outranks hook titles, the README
  recommends `claude --rc` without a name so the plugin title is used.

### 4.8 Logging and diagnostics

- Log file `$CLAUDE_CONFIG_DIR/session-namer/log.txt`, one line per
  event, rotated at 512 KB (rename to `.1`, keep one).
- `/session-name --doctor` prints: Node version, `claude` path and
  version, config dir, options in effect, last 20 log lines, and runs a
  dry title generation on a fixed sentence, reporting latency.

## 5. Configuration

Declared in `plugin.json` `userConfig` (prompted at enable time,
exported as `CLAUDE_PLUGIN_OPTION_<KEY>`), all optional:

| Key | Type | Default | Meaning |
| :-- | :-- | :-- | :-- |
| `model` | string | `haiku` | Model for topic generation |
| `separator` | string | ` - ` | Between project and topic |
| `max_words` | number | 7 | Topic word cap (min 3) |
| `timeout_ms` | number | 20000 | Generation timeout |
| `project_source` | string | `git` | `git` (repo root name) or `cwd` |
| `name_headless` | boolean | false | Also name `claude -p` sessions |
| `enabled` | boolean | true | Master switch |

Environment overrides (for scripts/CI): `CLAUDE_SESSION_NAMER=off`,
`SESSION_NAMER_MODEL`, `SESSION_NAMER_TIMEOUT_MS`.
Per-repo override file `.session-namer.json` at repo root:
`{"project": "...", "enabled": false}`. Read-only, no code execution.

## 6. Repository layout

```
claude-session-namer/
  .claude-plugin/plugin.json        # name, version, userConfig, hooks ref
  .claude-plugin/marketplace.json   # single-plugin marketplace
  hooks/hooks.json                  # SessionStart, UserPromptSubmit, Stop (exec form)
  hooks/namer.js                    # entry: node namer.js <event>
  lib/title.js                      # project/topic/sanitise/format (pure)
  lib/state.js                      # state files, pruning, config dir resolution
  lib/generate.js                   # spawn claude -p --bare, timeout, parse
  lib/config.js                     # options from env/userConfig/.session-namer.json
  commands/session-name.md          # /session-name [topic] [--remote] [--doctor]
  test/*.test.js                    # node:test, no deps; fixtures of hook inputs
  docs/superpowers/specs/...        # this spec
  README.md, README.pt.md, CHANGELOG.md, LICENSE (MIT)
  package.json                      # "test": "node --test", no dependencies
```

Runtime requirement: Node.js ≥ 18 on PATH (Claude Code's npm install
already requires it; native-installer users need Node separately, stated
in README and checked by `--doctor`). Zero npm dependencies.

## 7. Edge cases (explicit decisions)

| # | Situation | Decision |
| :-- | :-- | :-- |
| 1 | User started with `--name X` or renamed | `session_title` present → state `user`, never touched |
| 2 | Resume of a session titled by the plugin earlier | `session_title` equals stored title → keep stage, do nothing |
| 3 | Resume of an old untitled session | Provisional `<project>`; first eligible prompt finalises |
| 4 | `/clear` | Platform ignores `sessionTitle`; state left as is; next prompt eligibility unchanged |
| 5 | Compaction | Ignored |
| 6 | Fork | Treated like startup; new session_id → new state |
| 7 | Subagents | `SessionStart` with `agent_type` present → exit 0, nothing. `UserPromptSubmit` does not fire for subagents |
| 8 | Plugin enabled mid-session | No state file; first prompt goes straight to final title |
| 9 | Two sessions start simultaneously | State is per session_id; no shared writes |
| 10 | Two accounts (`CLAUDE_CONFIG_DIR`) | State/log under that dir; options read from that account's settings |
| 11 | cwd is home or a drive root | project = folder basename (`bruno`, `C`), documented; per-repo override not applicable |
| 12 | Folder name with spaces / unicode / very long | Kept as-is, trimmed to fit 80-char cap; unicode preserved |
| 13 | Git present but not a repo, or `git` missing | Fall back to cwd name; git is called with `--show-toplevel`, 2 s timeout, errors ignored |
| 14 | Worktrees | Repo root name via `git rev-parse --show-toplevel` of the main worktree is NOT used (differs per worktree); instead use `git rev-parse --git-common-dir` parent folder name so all worktrees share the prefix |
| 15 | Prompt is a slash command / shell / tiny / ack | Skip, stay provisional |
| 16 | Prompt is huge paste | Truncate head+tail before sending |
| 17 | Prompt contains secrets | Sent only to the user's own Claude account via their CLI, same as the prompt itself; documented |
| 18 | Model returns garbage, quotes, multi-line, "Title:" prefix | Sanitise; if still invalid → failure path |
| 19 | Model returns wrong language | Accept; few-shot examples minimise it; `/session-name <topic>` fixes |
| 20 | `claude` not on PATH inside hook (e.g. alias-only install) | Resolve via `process.execPath` sibling, `npm root -g`, `~/.local/bin/claude`, `%APPDATA%\npm\claude.cmd` (spawned via `cmd.exe /c` only in that case); else failure path + doctor hint |
| 21 | Offline / API error / rate limit / org policy | Failure path, silent, logged |
| 22 | Timeout | Child killed, failure path; attempts counter |
| 23 | Recursion | `--bare` skips hooks; plus env guard `SESSION_NAMER_NESTED=1` |
| 24 | Hook slower than the 30 s platform timeout | Internal 8 s cap guarantees never |
| 25 | Windows without Git Bash | Exec form needs no shell; `node.exe` resolved on PATH |
| 26 | Node missing | Hook fails to spawn; Claude Code reports hook error once per event. README + doctor. Considered acceptable vs. shipping shell scripts in two dialects |
| 27 | Old Claude Code without `sessionTitle` support | Output ignored harmlessly; README states minimum version 2.1.94 |
| 28 | Remote Control started with a name | That name outranks; README explains, suggests `claude --rc` without a name |
| 29 | VS Code shows stale ai-title | Stop re-assert once; README caveat |
| 30 | State dir not writable | Fall back to OS temp dir; if that fails, run stateless (may re-generate once) |
| 31 | Log growth | Rotate at 512 KB |
| 32 | Plugin update changes format | State stores `v`; mismatched version → treat as provisional, never as `user` |
| 33 | User disables mid-session | `enabled=false` read on every event |
| 34 | Headless `claude -p` runs | Skipped by default (`name_headless=false`) when detectable; otherwise at most one Haiku call |
| 35 | Session title emoji/ANSI from model | Stripped |

## 8. Testing

- Unit tests (`node --test`, no deps): title formatting, sanitising,
  truncation, project resolution (git/cwd/worktree via temp repos),
  eligibility rules, state transitions, config precedence, log rotation.
- Hook contract tests: feed recorded JSON inputs for each event and
  assert exact stdout JSON (or empty) and exit code 0, with the model
  call stubbed through an env var `SESSION_NAMER_FAKE_RESULT`.
- Integration smoke (manual + CI optional): `claude --init-only` in a temp
  repo with the plugin enabled, assert the SessionStart output; then
  `claude -p --bare` availability check.
- Cross-platform CI matrix: ubuntu, macos, windows (GitHub Actions),
  Node 18/20/22.
- `claude plugin eval` suite with 3 scenarios (pt prompt, en prompt,
  slash-command prompt) once the plugin exists.

## 9. Release

- Version in `plugin.json` (semver), CHANGELOG, tags.
- Install: `/plugin marketplace add brunobola/claude-session-namer` then
  `/plugin install session-namer@claude-session-namer`.
- README (EN) + README.pt.md: what it does, 60-second install, options,
  Remote Control section, VS Code caveat, privacy, troubleshooting,
  uninstall.

## 10. Open questions

None blocking. Two choices made by default, easy to flip later:
- Provisional title is `<project>` alone (not `<project> - <branch>`),
  so a final title is visually distinct from a provisional one.
- Topic language follows the prompt (user decision on 2026-09-10).
