# Agent support

session-namer started as a Claude Code plugin. The same `<project> - <topic>`
title now reaches thirteen other AI coding agents, each through the most
reliable mechanism that agent offers. Everything below was installed and
tested live on Windows 11 between 2026-11-03 and 2026-11-04, against the
version listed. CI runs the full test suite on Windows, macOS and Linux. Where
something was not proven, the table says so.

> **Install any of them with one command:**
> `npx -y github:brunobola-portfolio/claude-session-namer#v1.2.0 install <id>`
> (or `install --detect` for every agent on your `PATH`). See
> [install.md](install.md).

Adapters other than Claude Code are **beta**: they depend on agent APIs that
are young and sometimes marked experimental by their own vendors.

## How each one works

Every adapter shares the same core from [`lib/`](../lib): the project name
comes from the git repository (worktree-aware), trivial prompts never cost a
model call, the model's answer is sanitised, and a title the user set is never
overwritten. Only the "how do I set a title in this agent" part differs.

| Agent | Hook point | How the title is set | Topic generated by |
| :-- | :-- | :-- | :-- |
| Claude Code | `SessionStart`, `UserPromptSubmit` | `hookSpecificOutput.sessionTitle` | `claude -p` (Haiku) |
| Codex CLI | `SessionStart`, `UserPromptSubmit` hooks | Detached worker calls `thread/name/set` through the shared daemon (WebSocket via `codex app-server proxy`), naming the thread `<project>` first, or else through a private `codex app-server` | `claude -p`; `codex exec` with your OpenAI login is opt-in (`SESSION_NAMER_CODEX_GENERATOR=codex`) |
| Pi | Extension events | `pi.setSessionName()`, the same call `/name` uses | A cheap model from Pi's active provider, `claude -p` fallback |
| OpenCode, Kilo | Plugin `event` handler | `client.session.update({ title })` | `claude -p`, or OpenCode's native title plus the project prefix |
| Copilot CLI | Extension | The session's rename call | `claude -p` |
| Cline CLI | `TaskStart`, `UserPromptSubmit` hooks | `cline history update --title` | `claude -p` |
| Crush | `TurnStart` hook | Worker runs `crush session rename` | `claude -p`, or Crush's own title plus the project prefix |
| goose | Plugin hooks | Worker renames, then watches 15 s and sets it again over goose's auto-namer | `claude -p`, or goose's own title plus the project prefix |
| DeepSeek Harness | Session-title plugin slot | Returns the title to dsh | `claude -p` |
| Amp | Plugin `agent.start` | `amp threads rename` | `claude -p` |
| Grok Build | Hooks | Worker calls the agent protocol's `_x.ai/session/rename` | `claude -p` |
| Gemini CLI, Qwen Code | Hooks | Console title API on Windows, OSC 0 on macOS and Linux, from a worker that outlives the hook | `claude -p` |

## Terminal tab fallback

Gemini CLI and Qwen Code have hooks but no way to name a session. Writing into
their private session files would work until the next release and could
corrupt user data, so the adapters do not do that. Instead they put the title
where you look when you switch between agents: the terminal tab.

On Windows that needed two tricks. Hooks run through PowerShell,
which restores the old console title when it exits, so a short-lived worker
sets the title just after the hook returns. Qwen starts hooks without a console
of their own, so a tiny PowerShell helper attaches to Qwen's console to set it.

## Why not Factory Droid and Cursor CLI

Both were installed and examined. Droid even installs the Claude Code plugin
as-is, but it keeps only `permissionDecision`, `permissionDecisionReason`,
`additionalContext` and `updatedInput` from hook output, so `sessionTitle` is
dropped, and it redraws the tab title itself. Cursor CLI has no hook output,
flag or subcommand for titles, and rewrites the tab every 200 ms while it
works. Both offer a manual `/rename`. If either vendor adds a title field, an
adapter is a few dozen lines.
