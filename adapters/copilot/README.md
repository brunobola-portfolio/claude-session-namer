# session-namer for Copilot CLI

Names every Copilot CLI session `<project> - <topic>`, like the Claude Code
plugin: the project name when the session starts, then a 3 to 7 word topic
from your first real message, generated by your own `claude` CLI
(`lib/generate.js`). Status: beta.

| Tested with | OS | Date |
| :-- | :-- | :-- |
| Copilot CLI 1.0.105 | Windows 11 | 2026-11-03 |

## How it works

Copilot CLI hooks cannot set a title: `userPromptSubmitted` command-hook output
is dropped, and `sessionStart` output is not processed
([hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference)).
Copilot CLI **extensions** can, though
([about extensions](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-cli-extensions)).
They get the SDK RPC `session.rpc.name.set({ name })`, which writes the same
session name as `/rename` and `--name`.

| Moment | What happens |
| :-- | :-- |
| Extension joins the session | No name yet, or only Copilot's own auto-name from the first prompt: the name becomes the **project** |
| First eligible message you type | Topic generated in the background; name becomes `<project> - <topic>` |
| You `/rename` the session | Detected through `session.title_changed` plus `user_named`; the adapter never touches it again |

A name only counts as the adapter's own once `name.set` has succeeded, so a
failed write can never make your own identical rename look like ours.

The name is stored in `~/.copilot/session-state/<id>/workspace.yaml`
(`name:`, `user_named: true`). It shows up in the session picker and works with
`copilot --resume "<name>"`. Copilot sets the terminal tab to
`<name> - GitHub Copilot` by itself unless `updateTerminalTitle` is `false`.

The extension registers **no hooks and no tools**, so Copilot asks for no
extension permission. It adds one slash command:

| Command | Effect |
| :-- | :-- |
| `/session-name Meu tópico` | Name becomes `<project> - Meu tópico` and stays locked |
| `/session-name` or `/session-name --regenerate` | Back to the project name; your next message generates a new topic |

## Requirements

- Copilot CLI with its experimental mode on. Copilot labels extensions
  "experimental": run `/experimental on` once, start with
  `copilot --experimental`, or set `"experimental": true` in
  `~/.copilot/settings.json`.
- Node.js 18+ and the Claude Code `claude` CLI, logged in (same as the Claude
  Code plugin).

## Install

Recommended, one line:

```bash
npx -y github:brunobola-portfolio/claude-session-namer#v1.2.0 install copilot
```

The installer copies the runtime to `~/.session-namer/app/<version>` and writes
the extension shim described below. Then restart Copilot CLI.

Manual install, from the repository root (`<repo>`):

```bash
node adapters/copilot/install.js
```

This writes `~/.copilot/extensions/session-namer/extension.mjs` (or
`$COPILOT_HOME/extensions/...`). That file is a four-line shim. It imports
`@github/copilot-sdk/extension`, which Copilot only resolves inside its
extension folders, then starts `adapters/copilot/extension.mjs` from this
repository by absolute path. Keep the repository where it is, or rerun the
installer after moving it. Then restart Copilot CLI (or run
`/extensions manage` and reload).

A directory junction or symlink into `adapters/copilot` does **not** work.
Copilot 1.0.105 skips linked extension folders.

## Verify

Start a session: its name in the session picker becomes the project name. Send
a real message: a few seconds later it becomes `<project> - <topic>`, and the
terminal tab shows `<project> - <topic> - GitHub Copilot`.

## Uninstall

```bash
npx -y github:brunobola-portfolio/claude-session-namer#v1.2.0 uninstall copilot
```

Or by hand: `node adapters/copilot/install.js --uninstall`. It removes
`~/.copilot/extensions/session-namer/`, but only if the installer wrote it. You
can optionally delete `~/.claude/session-namer/copilot/` (state and log).
Session names already set stay as they are.

## Configuration

The adapter reads the same options as the plugin (`lib/config.js`):
`SESSION_NAMER_MODEL`, `SESSION_NAMER_TIMEOUT_MS`, `SESSION_NAMER_SEPARATOR`,
`SESSION_NAMER_PROJECT_SOURCE`, `SESSION_NAMER_CLAUDE_PATH`,
`CLAUDE_SESSION_NAMER=off`, and `.session-namer.json` at the repository root.

## Limitations

- `session.name.*` and `workspaces.getWorkspace` are marked `@experimental` in
  the shipped SDK typings. A future Copilot release may change them. The
  adapter falls back to `name.get` and fails silently, never blocking a
  session.
- In `copilot -p` (prompt mode), user extensions also load. Copilot stops them
  as soon as the answer is printed, so the topic only lands when the run lasts
  longer than the generation (about 3 to 5 s). An extension cannot tell prompt
  mode from interactive mode, so `name_headless` is not honoured here.
- A name set by this adapter counts as user-set (`user_named: true`) for
  Copilot, which then stops auto-naming the session from its summaries. That
  is the intent.
- Only Windows 11 was tested.
