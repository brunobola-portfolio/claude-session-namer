# session-namer for Gemini CLI

Gemini CLI has no supported way to name a session from a hook or extension, so
this adapter titles the **terminal tab** instead: `<project>` at start, then
`<project> - <topic>` a few seconds after your first real prompt. Gemini's own
session list (`/resume`, `--list-sessions`) is not changed. Status: beta.

| Tested with | OS | Date |
| :-- | :-- | :-- |
| `@google/gemini-cli` 0.66.0, under ConPTY (Windows Terminal, VS Code terminal) | Windows 11 | 2026-11-03 |

## How it works

Command hooks `SessionStart`, `BeforeAgent` and `AfterAgent` run `hook.js`. A
worker sets the console/terminal title. Why only the tab:

- Hook outputs are limited to `additionalContext`, `decision`, `llm_request`,
  `llm_response`, `toolConfig`, `tool_input`, `tailToolCallRequest` and
  `clearContext`. There is no title field (checked in the 0.66.0 bundle).
- There is no rename command. `/chat save <tag>` (or `/resume save <tag>`)
  names a checkpoint you create by hand. The `summary` in saved sessions is
  generated by Gemini's own model and stored in private session files, which
  this adapter does not edit.

On Windows, Gemini runs hooks through PowerShell, which restores the console
title when it exits. So the hook only hands off to a worker started with
`cmd /c start "" /b node hook.js --worker`. The worker keeps the console but
escapes the job object that would kill it. It sets the title with
`SetConsoleTitleW` (via `process.title`), waits until the wrapper shell has
gone, and sets it again. On macOS and Linux the hook writes OSC 0 to
`/dev/tty`. A hook with no controlling terminal falls back to the terminal of
its nearest parent process that has one (see the Qwen adapter).

Headless runs (`gemini -p "..."`) are skipped unless `name_headless` is on.
Gemini does not tell hooks whether it runs interactively, so the first hook of
a session reads the Gemini command line among its parent processes and looks
for `-p` / `--prompt`. On Windows that costs about 1 s of hidden PowerShell,
once per session.

## Requirements

- Gemini CLI with hooks.
- Node.js 18+ and the `claude` CLI, logged in (used for the topic).
- `ui.hideWindowTitle: true` in Gemini's settings (the installer sets it).

## Install

Recommended, one line:

```bash
npx -y github:brunobola-portfolio/claude-session-namer install gemini
```

The installer copies the runtime to `~/.session-namer/app/<version>`, adds the
three hooks and sets `ui.hideWindowTitle`.

Manual install: in `~/.gemini/settings.json` (or
`$GEMINI_CLI_HOME/.gemini/settings.json`), merge the following, with `<repo>`
replaced by the absolute path of your checkout (forward slashes):

```json
{
  "ui": { "hideWindowTitle": true },
  "hooks": {
    "SessionStart": [ { "hooks": [ { "type": "command", "name": "session-namer", "command": "node \"<repo>/adapters/gemini/hook.js\"", "timeout": 10000 } ] } ],
    "BeforeAgent":  [ { "hooks": [ { "type": "command", "name": "session-namer", "command": "node \"<repo>/adapters/gemini/hook.js\"", "timeout": 10000 } ] } ],
    "AfterAgent":   [ { "hooks": [ { "type": "command", "name": "session-namer", "command": "node \"<repo>/adapters/gemini/hook.js\"", "timeout": 10000 } ] } ]
  }
}
```

`ui.hideWindowTitle: true` is required. Without it Gemini rewrites the tab
(`◇  Ready (folder)`, `✦  Working…`) on every state change and the topic
disappears at the next turn.

In the VS Code terminal the tab shows the title only if
`terminal.integrated.tabs.title` contains `${sequence}`.

## Verify

Start `gemini` in a git repository: the tab shows the project name. Send a real
prompt: about 3 s later it shows `<project> - <topic>` and keeps it for the
rest of the run.

## Uninstall

```bash
npx -y github:brunobola-portfolio/claude-session-namer uninstall gemini
```

Or by hand: remove the three hook entries and, if you like,
`ui.hideWindowTitle`. Optional: delete `~/.gemini/session-namer/` (state and
log).

## Configuration

The shared options apply: `CLAUDE_SESSION_NAMER=off`, `SESSION_NAMER_MODEL`,
`SESSION_NAMER_SEPARATOR`, `SESSION_NAMER_TIMEOUT_MS`,
`SESSION_NAMER_PROJECT_SOURCE`, `SESSION_NAMER_CLAUDE_PATH`,
`SESSION_NAMER_NAME_HEADLESS` (also title `gemini -p` runs), and
`.session-namer.json` at the repository root.

## Limitations

What was verified on 2026-11-03: Gemini ran under ConPTY (node-pty) with a
sandboxed `GEMINI_CLI_HOME` and `GEMINI_API_KEY=invalid-placeholder-key`. The
model call failed with `API_KEY_INVALID`, while the hooks fired before it.

- With `hideWindowTitle: true`, the OSC 0 stream showed `claude-session-namer`
  at start, then `claude-session-namer - Login redirect loop Safari` about 3 s
  after the prompt. It stayed until the end of the run.
- With `hideWindowTitle: false`, Gemini wrote `◇  Ready (claude-session-namer)`
  and `✦  Working… (claude-session-namer)` around our titles.
- Not verified: a live Gemini session on macOS and Linux, and a signed-in
  session. The shared OSC 0 code, including the fallback for a hook without a
  controlling terminal, is tested on real ptys on Ubuntu and macOS in CI.
- Headless detection only sees `-p` / `--prompt` on the command line. A prompt
  passed positionally or piped on stdin is treated as interactive.
- Only the tab is titled; the saved session keeps Gemini's own summary.
